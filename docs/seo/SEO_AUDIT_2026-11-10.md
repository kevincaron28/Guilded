# Technical SEO / indexing audit — Guilded sites

> **Correction (10 Nov, 12 PM ET):** the "HTTP returns 500" finding was a false alarm. The 500 came from Grok Bot's own network, which blocks plain HTTP for every site. Cloudflare "Always Use HTTPS" has been on for the kcaron.top zone since 15 Oct 2026, so no fix is needed. The remaining items stand.


**Date:** 10 November 2026 (America/Toronto)  
**Scope (read-only):** https://guilded.kcaron.top and https://kcaron.top, both served by Cloudflare Worker `guilded-wow` in public repo `kevincaron28/Guilded`.  
**Code reviewed:** `origin/main` at `809c3d2b` (10 Nov 2026, 11:35 AM America/Toronto). No files were changed and nothing was deployed.  
**Method:** `curl` with a normal Chrome UA and with `Googlebot/2.1`; robots.txt and both sitemaps; host variants (http, www, trailing slash, `.html`); raw HTML (no browser JS except what the Worker already rewrote); Worker and site-build source.

Google Search Console was **not** connected in this pass. A verification file is already live (see “Already in good shape” and “Needs Search Console data”).

## Top 5 issues (plain language)

1. **HTTP is broken.** `http://guilded.kcaron.top/` and `http://kcaron.top/` return **500 Internal Server Error** from Cloudflare Pingora, with an empty body, instead of a 301 to HTTPS. Google often tries HTTP first. That alone can stall or block indexing.
2. **Many French URLs in the sitemap are not actually French for crawlers.** The Worker rewrites `?lang=fr` only on routes listed in `wrangler.jsonc` `run_worker_first`. `/start/`, `/docs/*`, `/guides/*`, `/reference/` and `/quebec-gold/` are missing. On those URLs Google gets English HTML, French in a `hidden` block, and a canonical pointing at the English URL — so the FR sitemap entries look like duplicates.
3. **The two hostnames compete.** `www.kcaron.top` returns 200 (no redirect to the apex). `kcaron.top` also serves Guilded product pages such as `/features/` and `/start/` at 200. The two homepages share the same hero (“Less organizing. More playing.”) and very similar titles. Google may index one and ignore the other.
4. **Leaderboards, recruitment and guild pages have no canonical and no hreflang.** They also pick French from the `Accept-Language` header when `?lang=` is absent, so the same sitemap URL can return English or French. Internal links add `?lang=en`, creating a second English URL. Edition and trailing-slash redirects use temporary 302/307 instead of permanent 301.
5. **Sitemaps and robots need a cleanup**, and we still need Search Console to see Google’s own exclusion reasons. The sitemaps have no `lastmod`, list 24 FR query-string URLs (some broken as in #2), and `robots.txt` allows `/me/`, `/auth/`, `/api/` and `/health`. A Google HTML verification file is already on both sites; we cannot tell from the outside whether the sitemaps were submitted or what Coverage says.

## High

### H1. HTTP (port 80) returns 500 instead of a 301 to HTTPS

**Evidence**

- `curl -I http://guilded.kcaron.top/` → `HTTP/1.1 500 Internal Server Error`, `Server: Pingora`, empty body. Same for `http://kcaron.top/`, `http://www.kcaron.top/`, `http://www.guilded.kcaron.top/`, and the same URLs with the Googlebot UA.
- HTTPS on the apex hosts is fine (200 + `Strict-Transport-Security: max-age=31536000` on static assets).
- The 500 is issued by Cloudflare’s Pingora edge **before** the Worker runs. There is no code in `worker/index.mjs` that can fix HTTP today, because the request never reaches it.

**Likely impact on indexing:** High. Googlebot still discovers and retries HTTP. A 500 is a crawl failure, not a signal to use HTTPS. Combined with HSTS missing on bot-proxied pages (see L3), this is the most likely *technical* blocker if pages are “discovered but not indexed” or show 5xx in crawl stats.

**Fix spec (Cloudflare config, owner action; not a repo patch by itself)**

1. In the Cloudflare dashboard for zone `kcaron.top`: enable **Always Use HTTPS** (SSL/TLS → Edge Certificates, or equivalent). Confirm SSL/TLS mode is **Full (strict)**.
2. Optional hardening, already queued as security item W2: send HSTS on bot-proxied responses too (`src/services/web-layout.ts` `SECURITY_HEADERS`, and `src/services/guild-page.ts` response headers) with at least `max-age=31536000` (includeSubDomains only if every subdomain is HTTPS).
3. Do not try to “fix” this with a Worker HTTP handler until HTTP requests actually reach the Worker; today they do not.

**Acceptance**

- `curl -sSI http://guilded.kcaron.top/` and `http://kcaron.top/` and `http://www.kcaron.top/` return **301** (or 308) with `Location: https://…` and no 5xx, for both a browser UA and Googlebot.
- After that, a follow-up request to the HTTPS URL returns 200 (or a further 301 to the canonical host — see H3).
- Search Console → Settings → Crawl stats should stop showing 5xx on `http://` URLs within a few days of the change (Kevin confirms in GSC).

### H3. Host and content duplication: www vs apex, kcaron.top vs guilded.kcaron.top

**Evidence**

- `wrangler.jsonc` L38–50 binds `kcaron.top`, `www.kcaron.top`, and `guilded.kcaron.top`. There is **no** `www.guilded.kcaron.top` route. `https://www.guilded.kcaron.top/` fails TLS (`unexpected eof`).
- `https://www.kcaron.top/` returns **200** with the same body as `https://kcaron.top/`. Canonical correctly points at `https://kcaron.top/`, but there is no redirect. Googlebot got the same 200.
- `https://guilded.kcaron.top/creator/` and `/creator/index.html` return **200** serving the kcaron.top homepage, with canonical `https://kcaron.top/`. Should be a 301.
- `https://kcaron.top/features/` and `https://kcaron.top/start/` return **200** (full Guilded pages). Canonicals point at `https://guilded.kcaron.top/…`, but the URLs remain crawlable because `https://kcaron.top/robots.txt` is `Allow: /`.
- Homepage titles are close enough to compete:
  - Guilded: “Guilded — Free WoW guild addon: EP/GP, loot, dungeons”
  - kcaron.top: “Guilded — Free WoW guild addon, by Kevin Caron”
  - Both H1s: “Less organizing. / More playing.”

Worker host switch is in `worker/index.mjs` L302–315 (`creator` hostnames only remap `/`, `/robots.txt`, `/sitemap.xml`). All other paths fall through to the Guilded asset tree.

**Likely impact on indexing:** High for “why isn’t my page the one that ranks?”. Google may treat the two properties as overlapping, pick a surprising canonical, or split crawl budget. www without a 301 is a classic duplicate. The similar homepages make it worse.

**Fix spec**

In `worker/index.mjs` `route()`, early, before asset/bot handling:

1. If `url.hostname === "www.kcaron.top"` → **301** `https://kcaron.top${url.pathname}${url.search}` (preserve path/query; `/` stays `/`).
2. If `url.hostname` is `guilded.kcaron.top` and path is `/creator`, `/creator/`, or `/creator/index.html` → **301** `https://kcaron.top/` (plus `?lang=` if present).
3. If `url.hostname` is `kcaron.top` or `www.kcaron.top` and the path is a Guilded product path (`/features`, `/start`, `/docs`, `/guides`, `/officers`, `/companion`, `/editions`, `/forever`, `/reference`, `/status`, `/quebec-gold`, `/g/`, …) → **301** to the same path on `https://guilded.kcaron.top`. Keep serving `/`, `/robots.txt`, `/sitemap.xml`, `/support`, and the Google verification file on kcaron.top.
4. Content (separate from redirects): rewrite `site/creator/index.html` so the creator homepage is clearly “K Caron Projects / Kevin Caron” (title, H1, description, JSON-LD `WebSite`/`Person`) and links to Guilded as a product, instead of repeating the Guilded hero almost verbatim. File: `site/creator/index.html`.
5. `www.guilded.kcaron.top`: either leave it unpublished, or add a fourth custom domain in `wrangler.jsonc` and 301 it to `https://guilded.kcaron.top`. Do not leave it as a TLS error if it will ever be typed or linked.

**Acceptance**

- `curl -sSI https://www.kcaron.top/` → 301 `Location: https://kcaron.top/`.
- `curl -sSI https://www.kcaron.top/?lang=fr` → 301 `https://kcaron.top/?lang=fr`.
- `curl -sSI https://guilded.kcaron.top/creator/` → 301 `https://kcaron.top/`.
- `curl -sSI https://kcaron.top/features/` → 301 `https://guilded.kcaron.top/features/`.
- `https://kcaron.top/` and `https://guilded.kcaron.top/` remain 200, with clearly different titles, H1s and descriptions.
- kcaron.top sitemap still lists only `https://kcaron.top/` and `https://kcaron.top/?lang=fr`.

### H4. Bot-served public pages: no canonical, no hreflang, language from Accept-Language, duplicate `?lang=en`

**Evidence**

Pages such as `https://guilded.kcaron.top/forever/leaderboards/`, `/forever/leaderboards/guilds/`, `/forever/recruitment/`, `/forever/recruitment/guilds/`, `/forever/players/`, and `https://guilded.kcaron.top/g/quebec-gold/` are rendered by the bot through `src/services/web-layout.ts` and `src/services/guild-page.ts`.

- Live HTML has title, description, og:title/description/image, `html lang`, and real server-rendered content (leaderboards HTML ~38 KB, visible text ~5.3 KB — not empty). **No** `<link rel="canonical">`, **no** `hreflang`, **no** `og:url`.
- `web-layout.ts` L12–16: if `?lang=` is missing, language is taken from `Accept-Language`. Confirmed live: `curl -H 'Accept-Language: fr-CA,fr;q=0.9' https://guilded.kcaron.top/forever/leaderboards/` returns `<html lang="fr">` and title “Classements des donjons · Guilded”, still at the unparameterized URL, still with no canonical.
- `link()` in `web-layout.ts` L21–28 always sets `lang`. Internal EN links go to `?lang=en`. Sitemap lists the clean URL without `lang`. Two English URLs, no canonical.
- FR bot URLs work (`/forever/leaderboards/?lang=fr` and `/forever/recruitment/guilds/?lang=fr` return French titles) but are **not** in `/sitemap.xml` (only the clean EN paths are, via `publicUrls` in `scripts/build-site.mjs` L147).
- These responses also omit HSTS (`SECURITY_HEADERS` in `web-layout.ts` L31–37 has no `strict-transport-security`). See L3.

`src/services/guild-page.ts` L219–223 has the same canonical/hreflang/og:url gap for `/g/{slug}/`.

**Likely impact on indexing:** High for the public data pages, which are the main reason to visit the site from search (leaderboards, “find a guild”, Quebec Gold). Unstable language at one URL and missing canonicals make Google treat variants as duplicates or “duplicate without user-selected canonical.”

**Fix spec**

1. `src/services/web-layout.ts` `layout()`: for indexable pages (`!input.noindex`) emit:
   - `<link rel="canonical" href="https://guilded.kcaron.top{canonicalPath}">`
   - `og:url` with the same value
   - `<link rel="alternate" hreflang="en" href="…canonical EN…">`
   - `<link rel="alternate" hreflang="fr" href="…?lang=fr">`
   - `<link rel="alternate" hreflang="x-default" href="…canonical EN…">`
   - Canonical EN path: the section URL **without** `?lang=` (and without other filter params that should be noindexed, or with a consistent minimal set — see below).
   - Canonical FR path: same path with only `?lang=fr`.
2. Change `langFrom()` so **public indexable** routes default to `"en"` when `?lang` is absent. Do not use `Accept-Language` to change the HTML of `/leaderboards`, `/recruitment`, `/players`, `/g/`. (Accept-Language can remain for `/me/` and other `noindex` pages.)
3. 301 `?lang=en` → the clean URL (strip `lang=en` only). Implement at the Worker for `GET` on those paths, or in the bot and allow the existing redirect pass-through.
4. Filter query strings (season, dungeon, class, realm, etc.): either add them to the canonical as the default “all results” URL and `noindex,follow` the filtered views, or canonicalize all filters back to the unfiltered page. Do not leave filtered URLs indexable without a self or parent canonical.
5. Same canonical + hreflang + og:url on `src/services/guild-page.ts` for published, indexable guild pages (canonical `https://guilded.kcaron.top/g/{slug}/`, FR `?lang=fr` if a French rendering exists).
6. `scripts/build-site.mjs`: add the FR bot section URLs (`/forever/leaderboards/?lang=fr`, guilds, recruitment, players) to the sitemap once canonicals are self-referencing. Keep `/g/{slug}/` only in the bot sitemap.

**Acceptance**

- `curl -s https://guilded.kcaron.top/forever/leaderboards/` (no `lang`, `Accept-Language: fr`) still returns **English** `html lang="en"` (or 302/301 to `?lang=fr` — pick one rule and test it). It includes a self-canonical to `https://guilded.kcaron.top/forever/leaderboards/` and hreflang fr to `…?lang=fr`.
- `curl -s https://guilded.kcaron.top/forever/leaderboards/?lang=fr` returns French, canonical `…?lang=fr`, hreflang back to the clean EN URL.
- `curl -sSI https://guilded.kcaron.top/forever/leaderboards/?lang=en` → 301 to `/forever/leaderboards/`.
- `https://guilded.kcaron.top/g/quebec-gold/` has a self-canonical and is listed in `/recruitment/guilds/sitemap.xml`.
- `/me/` remains `noindex` and is not added to any sitemap.

### H5. Temporary redirects (302 / 307) where a permanent 301 is needed

**Evidence**

- `https://guilded.kcaron.top/leaderboards/` → **302** `/forever/leaderboards/`.
- `https://guilded.kcaron.top/forever/leaderboards` (no trailing slash) → **302** `/leaderboards/?edition=forever` → **302** `/forever/leaderboards/` (two hops). Code: `worker/index.mjs` L339–351 (`cache-control: no-store`, status 302) and L333–336 (slash add is already 301 for section hubs only).
- `https://guilded.kcaron.top/recruitment/guilds/` → **302** `/forever/recruitment/guilds/`.
- Cloudflare Assets `html_handling: "auto-trailing-slash"` (`wrangler.jsonc` L94) issues **307** for `/start` → `/start/`, `/features` → `/features/`, `/docs/PRIVACY/` → `/docs/PRIVACY`, `/docs/PRIVACY.html` → `/docs/PRIVACY`. 307 is temporary; Google may not consolidate as cleanly as with 301.

Forever is now the only edition, so the “remembered edition” 302 is no longer a temporary preference — it is the permanent address.

**Likely impact on indexing:** Medium-high. Temporary redirects and chains waste crawl budget and can delay or weaken canonicalization of sitemap URLs vs the slashed or section-prefixed form.

**Fix spec**

1. In `worker/index.mjs`, once Forever is the only edition, use **301** (with a long `cache-control`) for:
   - `/leaderboards`, `/recruitment`, `/players` (and `/guilds` under them) → `/forever/…`
   - Retired edition sections already use 301 — keep that.
2. Normalize section paths with a **single** 301: `/forever/leaderboards` → `/forever/leaderboards/` directly. Do not bounce through `?edition=forever`.
3. For static HTML trailing-slash / `.html` cleanup, either:
   - handle those paths in the Worker with 301 (add the missing routes from H2 to `run_worker_first` and issue 301 before `ASSETS.fetch`), or
   - document that CF Assets 307 cannot be changed and add explicit 301 rules in the Worker for the public HTML routes.
4. Leave true temporary holds (e.g. a held PoE2 page if `POE_ENABLED` is false) as 302.

**Acceptance**

- `curl -sSI https://guilded.kcaron.top/leaderboards/` → **301** `Location: /forever/leaderboards/` (or the absolute HTTPS equivalent), one hop.
- `curl -sSI https://guilded.kcaron.top/forever/leaderboards` → **301** `Location: /forever/leaderboards/`, **one** hop, no `?edition=`.
- `curl -sSI https://guilded.kcaron.top/start` → **301** (not 307) to `/start/`.
- `curl -sSI https://guilded.kcaron.top/docs/PRIVACY.html` → **301** to `/docs/PRIVACY`.

## Medium

### M1. Sitemap quality and contradictory FR entries

**Evidence:** `https://guilded.kcaron.top/sitemap.xml` — 55 URLs (31 EN + 24 FR), absolute `https://guilded.kcaron.top/…`, **no** `<lastmod>`, `<changefreq>` or `<priority>`. Built in `scripts/build-site.mjs` L166–187 (rewritten twice; the second write is the one that ships). `https://kcaron.top/sitemap.xml` has only `/` and `/?lang=fr`, also no `lastmod`. The static source `site/creator/sitemap.xml` still has a `lastmod` of 2026-10-17, but the build overwrites it without one.

FR query URLs are listed even when H2 means they are not valid language alternates yet. `/status/` is in the sitemap (thin live-status page, 1.2 KB visible text, no hreflang). `/quebec-gold/poe2/` is in the sitemap as a French-only page with no hreflang (and is not in `run_worker_first`, so the Worker hold-redirect in `worker/index.mjs` L331 may never run).

**Impact:** Google can use a sitemap as a hint, not a command. Bad FR entries and missing lastmod do not usually *block* indexing, but they slow recrawl and add noise in GSC’s sitemap report.

**Fix spec:** After H2/H4 land, keep only URLs that 200, self-canonicalize, and match the hreflang pair. Add real `lastmod` from the git commit date or file mtime of the source page (do not invent dates). Consider sitemap `xhtml:link` hreflang annotations. Drop `/status/` from the sitemap or mark it `noindex` if it should not rank. If PoE2 is held, 301 or 302 it and **remove** it from the sitemap; if it is public, add hreflang or leave it as a single-language URL without a fake EN alternate.

**Acceptance:** Every `<loc>` in both sitemaps returns 200 (after one 301 at most), has a matching self-canonical, and is not `noindex`. `lastmod` is present and not in the future. GSC sitemap report shows 0 “couldn’t fetch” and 0 redirect errors once submitted.

### M2. `robots.txt` allows private and machine routes

**Evidence:** Both robots files are `User-agent: *` / `Allow: /` plus Sitemap lines (`scripts/build-site.mjs` L167; `site/creator/robots.txt`). `/me/` is `noindex` but still allowed. `/auth/login` 302s to Discord OAuth. `/health` returns JSON `{"ok":true,…}` at 200 with no `X-Robots-Tag`. `/api/*` is allowed.

**Impact:** Medium. The site is small, so crawl-budget waste is limited, but Google may still queue `/health` and sign-in URLs, and OAuth URLs are a messy crawl.

**Fix spec:** Update the Guilded `robots.txt` writer in `scripts/build-site.mjs` (and keep the Worker from overriding it):

```
User-agent: *
Allow: /
Disallow: /me
Disallow: /me/
Disallow: /auth/
Disallow: /api/
Disallow: /health
Disallow: /owner
Disallow: /owner/
Sitemap: https://guilded.kcaron.top/sitemap.xml
Sitemap: https://guilded.kcaron.top/recruitment/guilds/sitemap.xml
```

Also send `X-Robots-Tag: noindex` on `/health` and `/api/*` JSON as belt-and-suspenders.

kcaron.top robots can stay `Allow: /` once product paths 301 away (H3).

**Acceptance:** `curl -s https://guilded.kcaron.top/robots.txt` contains those Disallows. A robots tester (or GSC robots tester) reports `/me/` and `/health` as blocked. Public pages remain allowed.

### M3. Empty HTML 404s on unknown static paths

**Evidence:** `https://guilded.kcaron.top/this-page-does-not-exist-xyz` and `https://kcaron.top/nope` return **404**, `content-length: 0`, no body, no `X-Robots-Tag`. `wrangler.jsonc` `not_found_handling: "none"`. Guild-page 404s are fine (HTML + `noindex`).

**Impact:** Medium-low. A real 404 is better than a soft 404. An empty body is slightly worse for users and for Google’s understanding of the site, and it provides no internal links back to real pages.

**Fix spec:** Add a small branded 404 HTML document (EN/FR if cheap) with `noindex`, a short message, and links to `/` and `/start/`. Serve it only with HTTP **404** (Worker fallback when `ASSETS.fetch` is 404 for HTML navigations). Do **not** use `not_found_handling: "single-page-application"` (that would 200 and cause soft 404s).

**Acceptance:** Unknown paths still return 404; body is HTML with `noindex` and at least one link to the homepage. Existing real pages still 200.

### M4. Thin or generic metadata on a few public pages

**Evidence**

- `https://guilded.kcaron.top/forever/players/` — description is just “Players” (`web-layout.ts` falls back to the title when description is short/missing in some views; the crawled description was “Players”). Visible text ~1.9 KB.
- `/forever/recruitment/guilds/` — visible text ~1.2 KB (directory may be sparse). Status 200, not a soft 404, but thin.
- `/status/` — thin by nature; still in the sitemap.

**Impact:** Medium for those URLs ranking; they can also be “Crawled – currently not indexed” if Google finds little unique value.

**Fix spec:** Give `/forever/players/` a real unique description in the leaderboard/players page renderer (`src/services/public-leaderboard.ts` or the players list handler). Expand empty/sparse directory empty-states with helpful unique copy (how to appear on the list, what Guilded is) without stuffing. Decide whether `/status/` should be `noindex` or kept.

**Acceptance:** Players page description is a full sentence, unique from the title. Empty directory pages still 200 but read as useful landing pages, or return a documented 404 if a given view has no public data.

### M5. JSON-LD gaps and the kcaron.top social image

**Evidence:** Guilded homepage JSON-LD `SoftwareApplication` is not rewritten for `/?lang=fr` (still English). `operatingSystem` is `"Windows"` only (the product is also a WoW addon). kcaron.top `WebSite` JSON-LD is fine but the creator OG image is 328 KB PNG (`/creator/assets/social.png`).

**Impact:** Low-medium. Unlikely to block indexing; can hurt rich results and FR relevance.

**Fix spec:** Localize JSON-LD in `localized-assets.mjs` or ship `data-` language copies. Consider `operatingSystem` as a list or a more accurate type (`VideoGame` / addon wording in the description is already there). Compress or convert the creator social PNG (target &lt; 200 KB, 1200×630). Files: `site/index.html`, `site/creator/index.html`, `worker/localized-assets.mjs`.

**Acceptance:** `curl -s https://guilded.kcaron.top/?lang=fr` JSON-LD `description` / `inLanguage` include French. Rich-results test (GSC or Google’s tool) reports no errors on both homepages.

## Low

### L1. Query-string language (`?lang=fr`) is a weaker long-term pattern than `/fr/` paths

Google can index query-string language versions when canonical + hreflang are correct (and H2/H4 fix that). Path prefixes (`/fr/start/`) are easier for users and for some tools. This is a later migration, not the first fix. If it is ever done, 301 the old `?lang=fr` URLs and update sitemaps, hreflang, and `site/nav.mjs` `localizedHref`.

### L2. Intermittent TLS “unexpected eof” from this audit environment

A few HTTPS requests (`/docs/DEPLOY_ORACLE`, `/editions/`, `/docs/PRIVACY?lang=fr`, `/leaderboards/`, a couple of redirect follows) failed once with `curl: (35) TLS connect error: unexpected eof`, then succeeded on retry. May be the audit network or an edge quirk (HTTP/3 / Pingora). Not proven as a site bug. Check GSC crawl errors for a pattern before chasing it in code.

### L3. HSTS missing on bot-proxied HTML

Static pages send `Strict-Transport-Security: max-age=31536000` via `site/_headers`. Bot pages (`web-layout.ts` `SECURITY_HEADERS`, guild pages) do not. Already in the 10 Nov security review as W2. Small SEO plus security. Add the header on those responses when H1 is done, so HTTP is already redirected.

### L4. Structured-data extras

No `BreadcrumbList` or `FAQPage` on guides. Not required for indexing. Optional after the high items.

### L5. `/quebec-gold/poe2/` language and hold behaviour

Live URL returns 200, `html lang="fr"`, French-only, canonical self, no hreflang. It is in the sitemap. Because the path is not in `run_worker_first`, the Worker’s `POE_ENABLED` hold in `worker/index.mjs` L326–331 may not run. After H2 adds `/quebec-gold/*`, confirm the intended behaviour (public page vs redirect) and keep the sitemap in sync.
