# Guilded 8.0.1 final audit — 28 October 2026

The agreed 8.0 launch feature set is implemented in 8.0.1. This fresh review found
two additional issues in the participation status read path and spreadsheet
exports, and corrected stale development-status pointers. Corrections ship as
the deliberate 8.0.2 safety patch. Published addon/installer bytes,
protocol 2, points, privacy settings and frozen season policies are retained.
The owner's manual testing waiver remains explicit.

## Finding corrected

**P2 — in-game spreadsheet exports did not protect formula-like text.** The
companion CSV exporter already prefixes such text, but `/guilded sheet` could
paste a raid title such as `=1+1` as a formula. `CorePresentation.lua` now protects
text beginning with formula characters, including after whitespace, while
retaining numeric cells and plain decimal strings. Actual-Lua regressions cover
raid, attendance, loot and standings output and prove the saved title is unchanged.
This requires a new client patch rather than replacing published 8.0.1 bytes.

**P2 — participation status copied the entire season ledger into bot memory.**
`/participation status` previously fetched every award/reversal, including reasons
and actor IDs, to calculate a user's score, weekly participant count and top five
helpers. Memory use and transferred data therefore grew with the whole season.

`participation-summary.ts` now performs these calculations in one parameterized
PostgreSQL query, returning at most one summary and five helper rows. Original
awards are looked up by primary ID and season when classifying reversals. A
reversal this week can still cancel helper credit earned before the week. Other
seasons, spending entries and future weekly activity cannot affect the displayed
weekly result. Positive helper ties use a stable user-ID order. Earning, daily
caps, season scores and financial history are unchanged.

Regression coverage includes the service's authorization boundary and refusal to
fetch the full ledger, plus the disposable PostgreSQL rehearsal with old history,
local Monday boundaries, reversals, zero-net participants, top-five limits,
foreign seasons and empty results. This finding is not evidence that it caused
the earlier Aiven maintenance-associated warning.

## Fresh checks and release integrity

The audit rechecked all 21 anonymous GitHub asset downloads and all ten approved
CurseForge ZIPs. All match their release hashes. All 16 live EN/FR edition,
provider/navigation/sign-in and runtime checks pass. The installed Store package
is 8.0.1.0, Store-signed and status OK; its signature/certificate chain and submitted
application archive pass verification. The optional standalone EXE remains unsigned.

The private bug inbox has zero open member reports and four historical service
error groups. They are not automatically marked resolved. The Oracle service is
active with no warning-level journal entries since the 8.0.1 deployment. Its
memory/disk observations are not Aiven memory measurements. No paid plan or pool
increase was introduced.

The participation correction passed **341 files / 2,858 tests**, TypeScript,
ESLint, both addon validators and PostgreSQL/restore/Windows CI. The added export
safety regression and deliberate 8.0.2 packages repeat the full gates in
[release completion](V8_0_2_RELEASE_COMPLETION.md). Both dependency audits report zero vulnerabilities.
Linux/PostgreSQL/restore and Windows packaging CI must pass on the
reviewed source and merged main. Backend activation additionally requires a fresh
ledger preflight, verified database/application backup and authenticated encrypted
off-server recovery. Actual CI/deployment receipts are recorded with the audit PR
and privately in `backups/final-audit-8.0.1-2026-10-28/`.
