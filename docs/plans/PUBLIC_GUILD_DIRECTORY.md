# Public guild directory (PR #999, follow-ups in 1b)

Owner decision (15 November 2026): "we can show everything publicly": every guild seen in public runs, including guilds that never installed Guilded, with its member roster, scores, recent runs and top players. Only in-game data; never Discord IDs or private notes. `/delete-my-data` and the public deletion page keep working.

## Where guilds come from
- **Guilded guilds**: `GuildSettings.publicDungeonRuns`, as before (`/leaderboards/guild/<slug>`).
- **Observed guilds** (no Guilded server): `PublicRunPlayer.guild`, the in-game guild text the uploader's client showed (`GetGuildInfo`, unverified display text, 9.3+). `loadObservedGuilds` in `src/services/public-leaderboard.ts` reads ACCEPTED public run players, newest sightings first (cap 60,000, a warning is logged when hit), and `groupObservedGuilds` (`src/services/guild-public-stats.ts`) groups them.
- Grouping: folded guild name + realm. A row with no realm takes the realm of the same character elsewhere, else the only realm that guild name was seen on; otherwise it stays in its own bucket. Two characters minimum. A guild whose slug base equals a Guilded guild's is left to that guild's page.
- Older addresses (#999's plain name-realm slug, and the one from before the realm was known) are aliases that redirect to the stable slug.
- Address: `ig:<slug>` internally; the public slug is `<name>-<realm>-<6 hex>` derived from the folded name and realm alone (stable, never depends on other guilds).
- Faction is unknown for observed guilds (no source): they show under "All" and the new "Unknown" faction filter.
- Roster, scores and runs of an observed guild are the public run players with that guild text.

## Backfill
`src/services/public-run-guild-backfill.ts` runs once per bot start (8 minutes in), idempotent, only rows with no guild: first from `DungeonRunPlayer.guild` (same addon run id and character), then from Guilded rosters (`GuildRosterEntry`; the guild is the server's `WowGuild` when it has one, else the in-game guild its own companions reported (`CompanionDevice.wowGuildName`, at least 2 devices and no other name); the Discord server name is never used, since it is not the in-game guild; most servers have no WowGuild row, which made the first run (15 November) match nothing; migration `20270227000100` clears the looked-at marker so runs get one more pass). Roster matches only use the roster of the Discord server that holds the run itself. Every run is looked at once (`PublicRun.guildBackfillAt`, migration `20270226000100`), covered or not, so uncovered runs are not rescanned on every start; they get a guild when a companion re-sends them (the ingest fill).

## Deletion
`deleteMyData` (`src/services/data-deletion.ts`) first anonymises (before the main transaction, outside it, set-based and batched, safe to repeat: a failure aborts before anything else is deleted) the member's characters in public runs: the player row becomes `deleted-player-<row id>` (no display name, no guild; class, role and level stay so the run is unchanged), and the same names are replaced in the run's saved integrity, upload evidence and reporters. Guild pages are built from those rows and from `Character`, so the member disappears from them. Public duel rows (names, keys, guild text, member ids, and the reports' keys and evidence) are anonymised the same way (`deleted-player-<duel id>-w|l`). First-name-only legacy rows ("Kev" for "Kev Caron") are touched only when tied to the member another way (a run that also holds their full-name character or was uploaded by their Discord server; a duel side with their member id, or a report from their server or their character); another player who only shares a first name is left alone.

## Duels, realms and factions (PR 2)
- **Duels of observed guilds**: the guild's Duels tab (`/leaderboards/guild/<slug>/duels`, and `.json`) shows counted public duels (`PublicDuel`, the global ladder's rows) where either side carried the guild's in-game guild text on its realm (`observedGuildDuels`, `guild-public-stats.ts`; a side with no realm stored counts), against anyone: the ladder lists the guild's own players, the other side's result still counts for them, and a "Record against anyone" tile gives wins and losses. The guild list's Duels column counts them too. The duel rows are loaded once and shared (a one-minute memo in the store, dropped with the pages' caches).
- **PvP**: battleground and world PvP data only exist for Guilded servers' members (guild-private tables), so there is no public PvP panel for an outside guild; its guild page shows none.
- **Realm and faction pages**: `/leaderboards/guilds/realms/` (realms with guild counts per faction), `/leaderboards/guilds/realm/<realm slug>/` (the slug gets a short hash of the exact name when the base was cut or altered, so two long realm names never collide) and `/leaderboards/guilds/faction/<alliance|horde|unknown>/` render the guild ranking filtered to that realm or faction (the same table and filters as `/leaderboards/guilds/`); the guild page's realm and faction tiles link to them. The realm comes from a guild's stats (observed guilds: the grouping's realm).

## Open
- Faction inference for observed guilds (no source yet: they stay "Unknown").

Matching rule for deletion: names match the full name (the first-name alias only with a tie, see above); with a realm on both sides the realms must be equal; a realm-less row (or a member character without a realm) is taken only when the name is unique in the member's guild. The public pages' caches are cleared after a deletion.
